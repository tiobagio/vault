VALIDATED MEDIUM+ FINDING
================================================================================

1) GitHub auth — team display Name and Slug both mapped → cross-team policy escalation
Severity: Medium (privilege escalation to policies / identity groups of a different GitHub team)
Primary: builtin/credential/github/path_login.go verifyCredentials (~L266–279)
Related: sdk/framework/policy_map.go Policies; PathMap CaseSensitive=false (lowercases keys)
Identity path: same teamNames feed Auth.GroupAliases (~L93–99) → external group membership

Mechanism:
For every GitHub team in the configured org, Vault appends BOTH:
  - team.Name  (display name)
  - team.Slug  (when Name != Slug)
into teamNames, then TeamMap.Policies() looks up each string as a map key.
Docs/API require map keys in "slugified" form (website/content/docs/auth/github.mdx,
api-docs/auth/github.mdx). PathMap lowercases keys, so lookup is case-insensitive.

GitHub uniqueness is separate for names vs slugs: a team's display Name may equal another
team's Slug (e.g. privileged team Name="Security Admins" Slug="security-admins"; attacker
team Name="security-admins" Slug="security-admins-1").

Attack path (non-Vault-admin):
  1. Admin configures: vault write auth/github/map/teams/security-admins value=admin-policy
     (or identity group-alias name=security-admins → high-priv external group)
  2. Attacker with GitHub org permission to create teams creates team named "security-admins"
     (slug auto-suffixed because slug security-admins is taken).
  3. Attacker joins that team, authenticates to Vault with a PAT.
  4. verifyCredentials includes display Name "security-admins" in teamNames.
  5. TeamMap hit → admin-policy (and/or GroupAlias joins privileged external group).

Impact: Vault policy / identity-group privilege escalation without membership in the
intended GitHub team. Does not require Vault identity/admin capabilities—only GitHub
team-create (common in orgs) plus GitHub auth login.

Not rejected as "documented design": docs tell operators to map by slug only; they do not
document that arbitrary team display names are also authoritative map keys, nor the
cross-team Name↔Slug collision.

NEAR-MISSES (rejected for medium+ non-admin E2E bar)
================================================================================

A) Cert auth URI/DNS/email SAN ryanuber glob — multi-segment "*"
Where: builtin/credential/cert/path_login.go matchesURISANs/matchesDNSSANs/matchesEmailSANs
       using github.com/ryanuber/go-glob ( "*" matches across "/" ).
Example: allowed_uri_sans="spiffe://td/ns/*/sa/vault" also matches
         "spiffe://td/ns/evil/extra/sa/vault".
Rejected: attacker must obtain a leaf chaining to a Vault-trusted CA with a crafted SAN.
          Without non-admin issuance of such leaves, this is CA/misconfig-adjacent (same
          class as prior OCSP SSRF near-miss). Distinct from excluded CVE-2025-6037 (CN).

B) AWS IAM bound_iam_principal_arn trailing wildcard breadth
Where: path_login.go GlobbedStringsMatch on ARNs ending in "*".
Example: "arn:aws:iam::123:role/admin*" matches "...:role/administrator".
Rejected: intentional documented trailing-wildcard semantics; admin chooses the pattern.
          Host vs sts_endpoint / client cache already covered by prior review / CVE-2025-11621.

C) GitHub organization_id trust-on-first-use
Where: path_login.go when OrganizationID==0 calls setOrganizationID via login user's client,
       then persists.
Rejected: Organizations.Get(configured name) returns the real org ID for that name; locks
          correctly after first successful resolution. Spoofing requires controlling GitHub
          API / base_url (admin). Legacy-config hygiene issue, not auth bypass.

D) Identity entity merge / mergePolicies on upsert
Where: identity_store_entities.go mergeEntity; mergeEntityAsPartOfUpsert(mergePolicies=true);
       upsertEntityInTxn auto-merges when alias factors collide.
Rejected: reachable from identity entity/alias write APIs (identity-admin equivalent) or
          internal CreateOrFetchEntity races under lock. No non-admin E2E that assigns new
          policies without already holding identity write. Namespace checks present.

E) ACL path globs / segment "+" / parameter GlobbedStringsMatch
Where: vault/acl.go CheckAllowedFromNonExactPaths; strutil.GlobbedStringsMatch (leading/trailing * only).
Rejected: matching priority and empty-segment behavior covered by acl_test.go; no unintended
          cross-mount / sys escape without an overly broad policy already granted. ACL
          identity templating emits metadata verbatim by design (trusted identity data).

F) Plugin catalog Env/Args / symlink / reload (≠ CVE-2025-6000)
Where: vault/plugincatalog/plugin_catalog.go Set EvalSymlinks; sdk/helper/pluginutil run_config Env.
Rejected: requires sys/plugins/catalog register (admin). Symlink escape checked at Set;
          SHA256 enforced at run. Amplifier after plugin-admin, not a new auth bypass.
          Reload endpoints are sudo/root-gated; not audit-device RCE.

G) MFA Duo/Okta/TOTP remaining
Where: login_mfa.go validateDuo preauth "allow" short-circuit; UsernameFormat via
       identitytpl.PopulateString.
Rejected: Duo "allow" is Duo-side bypass user policy (environment-specific). UsernameFormat
          retargeting via alias metadata needs admin-configured format + attacker-controlled
          metadata; does not yield generic Vault MFA skip. Enumeration CVEs excluded.

H) Lease/token privilege retention after revoke / entity disable
Where: token_store Lookup gates on lease ExpireTime; identity policies re-derived live via
       fetchEntityAndDerivedPolicies; merged entity ID index for post-merge tokens.
Rejected: TokenPolicies baked at issue is intentional; IdentityPolicies update live on
          entity/group change. Revoke removes lease before further use under normal paths.
          No demonstrated race retaining elevated identity policies after revoke/disable.

I) yaml.Unmarshal / unsafe JSON into interface{}
Rejected: no authz-sensitive yaml.Unmarshal sinks in vault core auth path; command/format
          test-only usage. No new type-confusion bypass traced.
